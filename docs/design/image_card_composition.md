# 图像卡片组合与交互

本文件说明现有卡片如何组合共享能力。视觉规则仅维护在 [DESIGN.md](../../DESIGN.md#image-cards)；网格、分页、业务数据和图片加载由所属页面继续管理。

## 组件职责

| 模块 | 职责 | 不负责 |
|---|---|---|
| `ImageCardFrame` | 尺寸、圆角、绘制状态，以及信息、徽章、动作和覆盖插槽 | 下载、缓存、流式生成、资源查询 |
| `ImageCardAction` / `ImageCardActionRunner` | 动作身份、顺序、可用性、批量能力与异步执行状态 | 推断业务支持的批量语义 |
| `ImageCardActionRegion` | 卡片右键菜单和动作执行生命周期 | 页面选择状态 |
| `CardActionButtons` / `ImageCardInlineActions` | 图片覆盖操作与参数卡内联操作 | 复制另一份业务动作清单 |
| `ImageCardBatchScope` | 同一选择快照对应的批量工具栏、右键和更多菜单 | 把单项编辑对话框循环成批量操作 |
| `CardSelection` / `CardSelectionScope` | 稳定 ID、范围选择、快捷键与目标快照算法 | 合并不同页面的状态 |
| `CardDragSource` / `CardDragPreparation` | 唯一原生手势、完整资源快照与按需文件准备 | 用预览图替代原始资源 |
| `CardDropPolicy` / `readCardDrop` | 整组兼容性和完整读取；保留 Vibe 与精准参考的业务内容 | 自动执行编码或其他付费操作 |
| `ImageHoverPreviewController` | 悬浮预览的关闭、滚动与路由生命周期 | 接管页面详情查看器 |

已有 `LibraryCardCategoryBadge`、`LibraryCardFavoriteBadge` 继续承载资源库分类与收藏状态；流式图片和各库特有的预览内容保留原有实现，不在外壳重新加载。

## 接入现有业务

- 生成预览和历史使用 `SelectableImageCard`；本地图库使用 `LocalImageCard3D`；在线画廊使用 `DanbooruPostCard`；Vibe 库和精准参考库分别保留自己的 `VibeCard`、`PreciseRefCard`。
- 五类主卡片组合共享外壳、动作和交互模块。Agent 图片沿用共享内存图像/本地图像拖动适配，标签条目使用资源拖动与选择模块；生成参数卡使用内联动作组件，图像选择器使用统一接收策略。不要为了统一类名而合并这些不同的数据所有权。
- 动作回调返回真实 `Future`，执行器才能保持 loading、禁止重复执行并报告失败。按钮、菜单和批量条不得各自维护动作顺序或吞掉异常。
- 页面显式构造批量动作并标记 `supportsBatch`。需要一次确认的删除、分类和导出先固定目标；批次逐项记录成功与原始错误，操作成功后按实际完成项更新选择。读取失败不能假装整批完成。

## 选择状态

每个页面的 Provider 保存自己的稳定 ID 集合与锚点，公共算法不持有资源对象。当前展示 ID 顺序用于 Shift 扩选与全选；后台分页或回收 Widget 不得剪掉其他页的选中 ID。

右键/更多菜单作用范围取决于被打开的卡片是否已选中。已选中时使用选择快照与批量清单；未选中时保留原选择，仅操作该卡片。筛选、分类或来源切换由对应状态 owner 清理范围，删除只移除已完成删除的 ID。输入焦点位于 `EditableText` 时，卡片快捷键让位。

## 拖动与接收

1. `CardDragScope` 或页面选择适配在拖动开始时固定完整、有序且无重复 ID 的资源列表。禁止同时在同一卡片外套多个原生拖动源或再添加竞争的 Flutter 卡片拖动手势。
2. 内部 payload 保存轻量身份；本地图库分类与相簿使用路径适配，Agent 使用资源引用。库分类目标先解析整组资源，再应用分类或收藏。
3. Windows 虚拟文件由接收方请求时才准备。整组准备完成前不向任意文件流交付内容，取消时不创建新接收流，错误写入接收流并显示失败。非虚拟文件平台沿用 `GalleryDragFile` 的会话临时文件生命周期。
4. 普通图片仍经过现有元数据移除与水印流程。Vibe 使用 `.naiv4vibe` / `.naiv4vibebundle`，精准参考库使用 `.naipreciseref`；这些可移植资源保留恢复所需的编码、图片和参数。
5. `onPerformDrop` 返回前完成全部原生 reader 读取；会弹出目标选择或导入对话框的业务工作排到系统拖放循环释放后。不能在异步后台继续使用已经失效的原生 reader。
6. 多图目标接受完整兼容集合；单图选择器、预览替换和全局目标选择入口拒绝多项。全局入口不抢占本地图库分类拖动；Vibe 和精准参考优先进入对应资源面板。用户确认的付费编码规则保持原有流程。

这套模块不新增持久化数据或云同步类型。拖动快照、执行状态和临时导出文件不参与云备份。

## 验证入口

先运行相关 `scripts/test_affected.ps1` 批次：公共动作、选择算法、卡片菜单、拖动保护、虚拟文件流、接收策略，以及业务页面的选择和导入回归。交互测试断言作用范围、状态保留和所有动作可达；不能只断言无 overflow。

真实 Windows/Android 验收使用项目级 Dart/Flutter MCP 与已有开发会话。逐张检查主卡片、更多菜单、选中状态和参数卡；修改尺寸、方向或临时输入后恢复。MCP 未提供原生 OLE 手势时，以 `tool/ole_drag_inspector/` 检查文件格式和保护链，明确区分格式自检与实际从应用拖到资源管理器的验证。
